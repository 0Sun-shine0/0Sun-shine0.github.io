一道题选哪个数：我踩过的三次「阈值」坑

分镜密度、细节强度、光流冻结 三个不同领域的问题，最后都归结成同一件事：挑一个数，然后说清它是怎么来的。挑数字比写算法难。

2026-10-018 分钟算法踩坑图像处理

写代码里最难的部分往往不是逻辑，是在某个不确定的地方定一个数。

这类地方编译器帮不了你、单元测试也测不出来，只能靠你对问题的理解。我踩过三次，都在不同的项目里，但回头看是同一件事。

一、分镜阈值：怎么把「感觉」变成 2 和 4

T2Video 要把一首诗拆成几个「镜头」分别生成画面。最省事的做法是一句一镜，但这样有两个问题：

  • 五言短句（「空山不见人」）单独生成，画面信息量太低，出来就是一张不知所云的图
  • 意象密集的长句一次装不下，生成结果会丢元素

所以我要按每句的意象个数决定合并还是拆分。那么问题来了：几个意象算少？几个算多？

# 单句意象少于 2 个与相邻句合并，超过 4 个拆成两镜
SPARSE_IMAGERY = 2
DENSE_IMAGERY = 4

这俩数字不是拍的，是数出来的：我把能拿到的五言/七言律诗跑了一遍解析，统计每句的意象个数分布 1 个意象的句子单独成镜确实空，5 个以上的句子确实挤。

分界点就落在 2 和 4。

关键是在注释里写清楚来源：

# 这两个数是按五言/七言律诗的实际解析结果标的，
# 换成词或现代诗需要重标。

「这个数是怎么来的」比这个数本身更重要。 不然半年后自己看到 SPARSE_IMAGERY = 2，只会想「凭什么不是 3」。

二、细节强度：全局算一个平均数，还是分层看

判断画面是不是「糊成一团」，最直觉的指标是拉普拉斯方差 整幅图算一次，方差低说明边缘少、画面平。

这个指标在普通照片上很好用。但它在我这里失效了，原因很具体：水墨和写意风格本来就大量留白。

留白的画，整幅方差自然很低。于是它被判定为「糊」，然后被拦下重生成。

换个算法：不平均，取最强的一批

把画面切成 8×8 的小块，每块算平均边缘强度，然后只取最强的 5% 那批块再平均：

def detail_score(gray, block=8, top=0.05):
    edges = np.abs(cv2.Laplacian(gray.astype(np.uint8), cv2.CV_64F))
    rows, cols = edges.shape[0] // block, edges.shape[1] // block
    tiles = edges[:rows*block, :cols*block].reshape(rows, block, cols, block)
    means = np.sort(tiles.mean(axis=(1, 3)).ravel())
    count = max(1, int(means.size * top))
    return float(means[-count:].mean())

思路的变化是：从「整幅图平均有多清晰」变成「画面里最清楚的地方有多清楚」。

留白的画只要有主体（几根树枝、一只鸟），最强的那些块就会亮起来；而纯色画面所有块都接近零，仍然会被拦下。

实测四种合成素材：

素材 全局方差 分块取前 5%
纯色 0.00 0.00
平滑渐变 0.02 1.25
留白构图 0.31 56
棋盘格 4.2 91

看第三行：留白构图在全局方差下是 0.31（跟渐变的 0.02 同一量级，都会被误判成糊），但在分块指标下是 56（清晰地表明「有内容」）。

阈值最后取 1.0 正好落在「纯色 0.00」和「有任何内容 ≥ 1.25」之间。

换指标的本质是把不确定性从平均值里挪出去：全局平均要求每一块都清晰，分块取最强只要求有一块清晰。对留白风格来说，后者才是对的问题。

三、光流阈值：定了「冻结」，还得定「看多久」

判断视频是不是「冻住不动」，用 Farneback 光流：相邻帧算一次运动幅度，取整段平均值，低于某个阈值就算冻结。

第一版跑得很欢，跑完发现一个更根本的问题：全分辨率算光流慢一个量级，一段 10 秒的视频要跑几十秒。

而这个指标只需要知道「有没有动」，不需要精确到像素。所以先把帧缩到 320 像素宽：

MOTION_WIDTH = 320

if gray.shape[1] > MOTION_WIDTH:
    scale = MOTION_WIDTH / gray.shape[1]
    gray = cv2.resize(gray, (MOTION_WIDTH, max(1, int(gray.shape[0] * scale))))

提速立竿见影。但接着第二个问题来了：只看平均值会漏掉间歇性冻结。

一段视频里前 2 秒完全静止、后 8 秒正常运动，平均值照样过关。可观众看到的恰恰是开头那 2 秒的卡顿。

所以除了均值，我又加了一个比率和一个极值：

return {
    "mean_flow": float(flows_arr.mean()),
    "frozen_ratio": float((flows_arr < frozen_below).mean()),  # 多少比例是冻住的
    "max_jump": float(jumps_arr.max()),                        # 最大的帧间跳变
    "pairs": len(flows),
}

同一个物理量，用不同统计方式看，回答的是不同问题：

  • mean_flow 回答「这段整体动了吗」
  • frozen_ratio 回答「有没有一段是死住的」
  • max_jump 回答「有没有突然闪一下」

三个都不能省。

四次都撞在同一件事上

回头这三个例子，加上「假指标」那篇里的直方图相关系数，四次踩的是同一个坑：

坑 表面问题 实际问题
分镜阈值 2 还是 3 没人知道这个数的来源
细节强度 全局还是分块 用错了统计量（平均 vs 极值）
光流阈值 阈值定多少 定完阈值没定「怎么用」
直方图相关系数 阈值 0.7 合理吗 指标本身病态，阈值无意义

共同点是：这些数字在代码里都只需要一行赋值，但背后要回答的问题往往要写一整段注释。

所以现在我定这类数时强迫自己做三件事：

一、写完数字，下面必须有一行注释说明它是怎么标定的。「实测标定」「按 X 素材试出来的」「暂时拍的，待重标」都可以，但不能什么都不写。写不出标定方法，说明这个数还没想清楚。

二、构造两个「应该过」和「应该拦」的样本，用它们验证阈值。 定 1.0 之前，我先造了纯色（该拦）和留白（该过）两张图。只测一个方向是不够的。

三、问自己「这个数的单位是什么」。 分镜阈值是「个数」，细节强度是「边缘能量」，光流是「像素位移」 说不出单位，通常说明这个指标本身没定义清楚。

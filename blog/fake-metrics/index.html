我写过两个「假指标」，直到它们骗了我自己

一个拿轮廓个数当物体检测、去跟关键词个数比大小；一个直方图相关系数低于 0.7 就报警。两个都跑得通、都看着合理，但都没有意义。附一个能说明问题的实测：同一张图与其压缩首帧的 SSIM 是 0.998，直方图相关系数却是 -0.0015。

2026-09-309 分钟算法踩坑图像处理

「验证」这件事，我以为自己会做。直到我把两个假指标写进项目，还让它们跑了半年。

第一个假指标：数轮廓当物体检测

T2Video 要判断「生成的画面跟诗里写的对不对得上」。我没有多模态模型，又不想让这一环空着，于是写了这么一段：

# 从文本里提取关键词
# 从图像里检测对象
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
detected_objects = [c for c in contours if cv2.contourArea(c) > 500]

if len(detected_objects) < len(keywords) * 0.5:
    errors.append("图像内容与文本描述不符")

注释里我自己都写了「简单物体检测（实际应用中应使用深度学习模型）」，但代码照跑不误，日志照报不误。

它错在哪？ findContours 数出来的是连通区域的个数。一张纯白云的照片，可能只数出 1 个轮廓；一张全是噪点的废图，能数出几百个。而 keywords 是中文词的数量。

这两个数之间没有任何可以比较的语义。数出 3 个轮廓、诗里有 5 个意象，说明不了任何事 但它们的大小关系是确定的，所以这段判断每次都「有结论」，只是结论是随机的。

更糟的是界面上写着：

物理验证确保运动合理性，历史验证确保场景准确性

这两项验证，代码里根本不存在。我当时的设计里确实打算做，写着写着忘了，但界面文案先写上了。于是它变成了一句纯装饰的承诺。

第二个假指标：直方图相关系数

这个更隐蔽，因为它看起来有数学依据。

我要判断「图像和视频首帧的色调是否连续」。直觉上，两张图色调接近，它们的灰度直方图应该长得像，那就用相关系数衡量：

hist_img = cv2.calcHist([gray_a], [0], None, [256], [0, 256])
hist_vid = cv2.calcHist([gray_b], [0], None, [256], [0, 256])
corr = cv2.compareHist(hist_img, hist_vid, cv2.HISTCMP_CORREL)
if corr < 0.7:
    errors.append("图像-视频连续性低")

相关系数落在 [-1, 1]，0.7 这个阈值看着也很合理。问题在于：没人会怀疑它。

直到我有一次用同一张图去比它自己压缩后的视频首帧 这两张画面肉眼几乎一模一样，SSIM 是 0.998。同一个对比，直方图相关系数给出的是：

直方图相关系数 = -0.0015

-0.0015。 一张图跟它自己比，相似度接近零。

为什么是负的

HISTCMP_CORREL 算的是两个直方图向量的皮尔逊相关系数。它的公式里有一步是减去均值再除以标准差。

当画面色调集中、对比度不高时（水墨、留白、整体偏灰的画面），256 维的直方图向量里绝大多数格子接近 0，只有少数几十个格子有值。这样的向量方差极小 分母趋近于零，相关系数就由极小的数值扰动决定了。它变得病态（ill-conditioned）。

换句话说：不是「两张图不像」，而是「这个指标在这种输入上算不出有意义的值」。它是坏的，不是不准的。 这两者的区别很重要：不准可以调阈值，坏掉只能换指标。

换成什么

我最后只留下能算出来的量。

色调连续性换成亮度均值差 就是两个灰度均值相减取绝对值。粗糙，但它在任何输入上都有定义、都稳定：

def brightness_gap(a, b):
    ga, gb = gray_of(a), gray_of(b)
    return abs(float(ga.mean()) - float(gb.mean()))

纹理清晰度也不用全局拉普拉斯方差。原因是：水墨和写意风格本来就大量留白，整幅图的方差天然很低，用全局方差会把正常作品误判成「糊」。改成把画面切成 8×8 的小块，只看边缘能量最强的 5% 那批块：

def detail_score(gray, block=8, top=0.05):
    edges = np.abs(cv2.Laplacian(gray.astype(np.uint8), cv2.CV_64F))
    rows, cols = edges.shape[0] // block, edges.shape[1] // block
    tiles = edges[:rows*block, :cols*block].reshape(rows, block, cols, block)
    means = np.sort(tiles.mean(axis=(1, 3)).ravel())
    count = max(1, int(means.size * top))
    return float(means[-count:].mean())

同一套参数在合成素材上实测：

素材 detail_score
纯色 0.00
平滑渐变 1.25
留白构图 56
棋盘格 91

阈值取 1.0，正好卡在「完全空白」和「有任何内容」之间。纯色被拦下，留白的水墨不会被误伤。

还有一个决定：不做假装检测

文本和图像之间的语义对齐（这首诗写的是「孤舟」，画面里真有船吗），没有多模态模型是算不出来的。

我本可以再写一段轮廓计数糊弄过去。但这次我选择让它明确返回 skip：

def check_semantics(text, image_path, scorer=None):
    if scorer is None:
        return {"status": "skip", "reason": "未接入语义打分器"}
    return scorer(text, image_path)

界面上也照实显示「已跳过（未接入打分器）」，而不是显示一个绿色的对勾。

接 CLIP 只需要传一个函数进来，但在接上之前，它诚实地什么都不说。

三条能带走的东西

一、指标必须有语义。 拿轮廓个数比关键词个数，就像拿人数比体重 两个数都算得出来，但比较它们不产生信息。写验证之前先问一句：这两个数在物理上为什么可比？

二、警惕「看起来有数学依据」。 相关系数、方差、熵这些量有公式、有名气、有默认阈值，反而更容易混过去。先拿一个「应该得高分」的样本去测（比如同一张图的两份拷贝），如果它给不出高分，这个指标就是坏的。

三、宁可 skip，不要假装。 缺模型就写「跳过」，缺数据就写「未标定」。一个假装在工作的检查项，比没有检查项更危险 因为你会因为它的对勾而放过问题。

最后

这两个假指标不是能力问题，是态度问题：我当时想让功能看起来完整，于是先写了调用点和界面文案，把真正的实现留给了「以后」。

后来我把这类规矩写成了代码卫生测试（禁止 print、禁止裸 except、禁止横幅注释），第一次跑就抓出我自己刚写的 9 处。靠自觉真的不行。

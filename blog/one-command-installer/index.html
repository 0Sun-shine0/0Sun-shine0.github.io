我是怎么做出一个能双击安装的版本的

把 Python 桌面应用做成「双击、下一步、完成」，比写功能更容易漏细节。打包流水线、自己写的安装向导、会自删的卸载器，以及安装版和绿色版怎么共用一套程序。

2026-09-279 分钟打包发布PyInstallerWindows

「装完就能用」这句话，落到工程上是一整条流水线。用户看到的只是双击一个 exe，但在这之前有一堆必须做对的事 —— 而每一件做错的后果都是「用户装不上」或者「用户装上了但数据丢了」。

一条命令把整条流程跑完

.venv\Scripts\python.exe tools\build.py --installer --zip
  1. 跑一遍自测（不通过就不打包）
  2. 生成多分辨率图标 build\pawpet.ico
  3. PyInstaller 打成 dist\PawPet\（onedir，解压后约 297MB）
  4. 真的启动一次打出来的 exe 验证能跑
  5. 压缩成 build\payload.zip（110MB）
  6. 打成单文件安装程序 dist\小爪助手-安装程序.exe（约 120MB）
  7. 端到端测一遍安装流程
  8. 生成绿色版 dist\小爪助手-<版本>-绿色版.zip

两个地方值得单独说：第 1 步和第 4 步。

第 1 步：打包是最贵的一步（几分钟），所以让它「有门槛」 —— 自测不过直接停，别浪费在打包上。

第 4 步：「打出来的 exe 真的启动一次」。这一步听起来没必要（源码跑得好好的），但它能挡住一整类只在打包后出现的问题：缺 DLL、Qt 插件没被收进去、相对路径在冻结环境里失效。这些问题在源码模式下永远测不出来。

安装向导：我为什么没用 Inno Setup

build/setup_ui.py 是用 tkinter 自己写的安装向导，不依赖任何第三方安装器工具。理由很简单：不想为了出一个包，再引入一套要单独维护、单独学的构建依赖。

向导里能选：

  • 安装位置：默认 %LOCALAPPDATA%\Programs\PawPet —— 不需要管理员权限
  • 创建桌面快捷方式
  • 开机自动启动
  • 安装完成后立即运行

安装时它做的事：

  • 把内嵌的程序解压到目标目录
  • 用 WScript.Shell 建 .lnk 快捷方式（开始菜单 + 可选桌面）
  • 写卸载信息到 HKCU\...\Uninstall\PawPet —— 于是**「设置 → 应用」里能看到它**，用户不会觉得这是个删不掉的野程序
  • 把自己复制成 uninstall.exe，作为卸载程序

默认装到用户目录、不申请管理员权限，是个刻意的选择。要 UAC 提权的安装包，会让一部分用户直接放弃；而放在 %LOCALAPPDATA% 完全够用。

卸载器：怎么把自己删掉

卸载流程里有两个坑，都是「不做就删不干净」的那种。

第一个：正在运行的实例会让文件删不掉。

所以卸载器的第一步是 taskkill 掉正在跑的小爪。这不是「顺手」，是必须 —— 否则后面每一步都在跟被占用的文件较劲。

第二个：卸载程序没法删掉自己。

Windows 上正在执行的 exe 是被锁住的，删不掉自己。解法是起一个延迟的 cmd 来做收尾：

taskkill 实例
   删程序文件
   删快捷方式
   删注册表项（「设置 → 应用」里那条）
   删开机自启项
   问一句：要不要删数据？默认保留
   起一个延迟 cmd，把自己删掉

「要不要删数据，默认保留」这一条是我最在意的。 %APPDATA%\PawPet 里是用户的待办、便签、提醒和专注记录 —— 那比程序本身重要得多。程序随时能重装，攒了几个月的数据没了就是没了。所以默认是保留，而且问的时候说清「保留」是默认选项。

同一个 exe，同时支持安装版和绿色版

数据放哪这件事，比想象中复杂。程序可能以四种方式运行，每种情况下「能写的位置」都不一样：

运行方式 数据位置 为什么
源码运行（新环境） 项目目录 .cache/runtime 和源码、构建产物隔离，不污染工作区
源码运行（检测到旧数据） 项目目录旁边 兼容旧版，避免已有数据看起来「丢了」
绿色版（exe 旁边可写） exe 旁边 便携，能塞 U 盘带着走
安装版（Program Files） %APPDATA%\PawPet 安装目录只读，写不进去

判断顺序是：先看有没有被 PyInstaller 打包，再看所在目录能不能写。

这个顺序是关键 —— 它让同一个 exe 既能当安装版也能当绿色版：放在可写目录旁边就便携，放在只读目录就自动去 %APPDATA%。不需要两个构建产物，也不需要用户理解区别。

另外还留了两个环境变量出口：PAWPET_HOME 强制指定数据目录（自动化测试用这个），PAWPET_DEV_HOME 指定开发数据目录。

兼容旧数据这一条也是刻意的。 如果项目根目录已经存在旧版的 pet_data.json、.env 或对话文件，程序会继续使用根目录，不会自动搬动或覆盖 —— 用户不会因为升级一次就以为数据丢了。

一个容易忽略的坑：.cmd 最好保持纯 ASCII

启动脚本 启动小爪助手.cmd 里，注释和提示一度是中文的。结果是脚本偶尔报：

'"D:\pet\"' is not recognized as an internal or external command

原因值得记一辈子：cmd.exe 用系统 OEM 代码页解析 .cmd 文件（中文 Windows 上是 GBK）。UTF-8 编码的中文字符，其字节序列末尾可能被 GBK 当成双字节字符的首字节，于是它把后面的换行符一起吃掉了 —— 两行命令粘成一条乱命令。

修法：启动器里的注释和提示一律用英文，中文提示交给 Python 弹窗。不要让 cmd 去解析中文。

写在最后

做完这条链路之后我的感受是：「装完就能用」不是打包的附加项，它就是产品的一部分。

功能做得再好，如果用户卡在安装、或者装完发现数据不见了，他不会觉得「这个工具不错，只是安装有点问题」 —— 他会直接不用了。所以这条流水线上的每一步（自测、真启动验证、默认保留数据、不申请管理员权限、兼容旧数据）都不是锦上添花，而是让产品能成立的必要条件。
